这份清单只说三件事：**点哪里**、**应该看到什么**、**我该查什么**。

"应该看到"里写了失败长什么样 —— 只说"应该能显示"的清单分辨不出「正常工作」和「悄悄空了」，
而这个项目反复出现的正是后一类 bug。

前置：`adb -s 127.0.0.1:16384 logcat -c` 先清日志，点完告诉我，我按下面第三列去查。

### 判据（1）为什么与实现不同

判据原文要求"不再把 Rust 核心塞进 APK 作为主路径、后端地址可配置"。
但后续明确的架构约定是：**手机始终跑自己的进程内核心，同步是 core↔core 协商，不是
frontend→远端核心**。

实现遵循的是后者。理由：手机要能离线打开已同步的数据；且 core↔core 让两端共用同一套命令与
读模型，不会出现"前端适配远端核心"的第二套语义。这一点写在这里，是因为它是对判据原文的
**偏离**，不该被含糊过去。

### 判据（2）现在到哪一步

已成立（数据库对账，手机库 vs 修复前复制的那份）：

```
_sync_row_version   418,690 → 418,692
sync.pullCursor     838,977 → 839,149
cycleHistory        每 15s 一轮，反复 {"pulled":2,"pushed":2,"error":null}
手机库最新行：self_profile_log ["2026-11-16T22:57:33.833Z","bio",""]、两条 configs
复制件最新行：feed_avatar  ["2026-11-16T20:46:12…"]
```

未成立：动态四张表与复制件**逐表相同**（132,779 / 17,768 / 1,691 / 104,816 行，最新时间一致）。
远端自 20:46 后没有新动态行，所以"新动态经同步出现在界面"没被观察到。

**要验证它，需要**：

1. 桌面端 VRCX 保持运行并录制，产生新的动态
2. 手机保持运行（每 15s 拉一轮）
3. 我查：手机库 `usred3295…_feed_gps` 的 `MAX(created_at)` 与行数是否**超过复制件**，
   以及动态页顶部是否出现该条

（feed 表名带 owner 前缀，裸 `feed_gps` 会报 no such table。）

我没有通过往共享库插假动态来制造这个证据 —— 那会污染所有设备上的真实动态流。

## 1. 好友动态（后端读模型 + 同步）

**点**：首页 → 动态 → 依次切换 全部 / 上线/下线 / 位置变动 / 状态/简介变动 / 模型变动

**应该看到**
- 每个 tab 顶部都是**该类型最新的一条**（不是更旧的）
- 模型变动行有"更换前 / 更换后"两张图
- 位置行显示世界名 + access 标签（好友+ / 群组 / 私密）
- 不同 tab 的顶部时间不同（位置↔状态↔模型各自最新）

**失败长什么样**
- 切 tab 后顶部时间**变旧** → `observeThrough` 语义又错了
- 全部 tab 空、其他 tab 有内容 → 空集合过滤又出问题
- 行里出现 `wrld_xxxx` 裸 id → 世界名没查到

**我查**：`feed page:` 日志的 `firstAt`，以及 `app__feed_rows_query` 的返回顺序

## 2. 收藏四页（实体 + 分组 + 详情）

**点**：收藏 → 玩家 / 世界 / 模型 / 群组，各切一个分组

**应该看到**
- 玩家：头像 + 名字 + 状态点
- 世界：封面 + 世界名 + 作者
- 模型：缩略图 + 模型名 + 作者
- 群组：群组图标 + 名字
- 切分组后列表**跟着变**（不是一直显示全部）

**失败长什么样**
- 某个 tab 空但"全部"有计数 → 分组标签没对上
- 一行显示 `avtr_xxx` 裸 id → 详情没 hydrate 到（可能是 VRChat 返回 `???`）

**我查**：`FavoritesBaselineCache` 的条目数、`remoteFavoritesById` 的类型分布

## 3. 通知（本地读模型 + 标记已读）

**点**：通知 → 点一条**未读**的（右侧有蓝点的那种）

**应该看到**
- 列表带封面、群组名、`群组通知` / `申请加入` 标签
- 点未读后蓝点消失，红点计数减少

**失败长什么样**

**我查**：`app__notification_mark_seen_batch` 的返回，以及有没有 `Batch action requires an
authenticated session.`

> 写操作。守卫已验证（无会话时给可读错误），成功路径要靠你这一下。

## 8. 数据同步（设置页）

**点**：头像菜单 → 设置 → 隐私与数据 → 数据同步；先看，再点「立即同步」

**应该看到**
- 同步状态：**已连接**
- 服务器：`100.70.120.64:5432 / vrcx0`
- 最近一次同步：一个**近几分钟内**的时间（不是冻结的 20:46）
- 点「立即同步」后该时间**往后跳**

**失败长什么样**
- 显示"未配置" → 库里 `config:vrcx_remotesync.*` 没了
- 时间一直不变 → **同步循环没跑**（`start_data_services()` 被漏掉时就是这样）
- 显示错误文本 → 连不上共享库（Tailscale 断了？）

**我查**：库里的 `_sync_meta.lastCycleAt` 与 UI 显示的对比
